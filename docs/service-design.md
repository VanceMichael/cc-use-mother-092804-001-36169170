# 照护服务设计

本文件说明 `src/panda_care/` 如何把领域约束落到事件与规则上。示例只使用虚构标识，
不含真实个人信息、账号或凭据。

## 1. 连续档案（事件流 + 阶段门禁）

所有业务事实都是只追加事件（`models.EventType`），按时间排成哈希链：

```
出发前评估 PRE_DEPARTURE → 装运封存 CRATING → 航程 FLIGHT → 入园适应 ADAPTATION
```

- 阶段只能由双方项目管理机构（`Role.AUTHORITY`）推进，且一次只能前进一格；
- 推进必须附已存在的依据事件（评估结论、封存记录、落地事件等）；
- `occurred_at` 是业务发生时间，`recorded_at` 是入链时间；争议回放以入链时间为准，
  允许补录但不允许倒填掩盖。

## 2. 责任留痕与只追加

- 每条事件都有 `actor_id`（责任人）、`occurred_at`、`phase`；
- 喂养、用药、体重、行为异常因此天然带时间和责任人；
- 台账（`ledger.Ledger`）只暴露追加接口，没有修改/删除接口；
- 每条事件保存 `seq / prev_hash / hash`（SHA-256，规范化 JSON），
  `verify()` 重放全链；快照可存 JSON，恢复时强制校验，任何字段被改都会失败。

## 3. 兽医结论锁定

- `VET_CONCLUSION` 一经确认即为锚点，饲养、用药、报告矛盾判定都引用它；
- 结论不能改写。修正只能新增一条结论并在 `supersedes` 指向旧结论，旧记录保留；
- 已被取代的结论不能再次被修正，避免分叉。

## 4. 范围化事件与恢复条件

四类异常事件统一为 `EFFECT_STARTED / EFFECT_RESOLVED`，用 `Scope` 精确挂接：

| 事件 | 挂接范围 | 未恢复时的影响 |
| --- | --- | --- |
| 检疫 `QUARANTINE` | 具体动物 | 该动物不得进入航程/入园阶段；不得交接 |
| 航线延误 `FLIGHT_DELAY` | 航程阶段（`phase_limited`） | 不能离开航程阶段 |
| 饲料替代 `FEED_SUBSTITUTION` | 具体计划条目 + 替代批次 | 原批次投喂被拒，只允许替代批次；其他条目/动物不受影响 |
| 单只隔离 `ISOLATION` | 具体动物 | 不阻断整体阶段；该动物喂养记录带隔离标记，且不得交接 |

规则要点：

- 开始事件**必须**写明 `recovery_condition`，替代必须给替代批次；
- 解除必须留存满足恢复条件的证据，且同一事件不能重复解除；
- “只影响相关环节”靠 `Scope`（动物 / 计划条目 / 批次 / 阶段）实现，
  例如平平隔离时，福双的喂养与交接照常。

## 5. 报告幂等与矛盾复核

`CareService.upload_report` 以报告**内容哈希**为幂等键：

1. 无矛盾 → `ACCEPTED` 归档；
2. 与任一现行兽医结论冲突 → 生成 `REVIEW_OPENED` 转**指定复核兽医**，
   状态 `REVIEW_PENDING`，冲突结论在复核期间挂起（不能作为用药等照护依据）；
3. 重复上传同一份内容：
   - 复核中 → 返回 `REVIEWING`；
   - 已出结论 → 返回终态 `REVIEW_ACCEPTED / REVIEW_REJECTED`；
   - 始终返回原报告事件 id，不产生任何新事件。

指定兽医的复核决定（`REVIEW_RESOLVED`，只能作出一次）：

- `ACCEPT_REPORT`：为每条冲突结论追加同议题新结论并 `supersedes` 旧结论；
- `REJECT_REPORT`：维持原结论，报告保留但不作为照护依据。

## 6. 权限

`service.PERMISSIONS` 按事件类型限定角色，例如：

- 阶段门禁仅管理机构；航程事件仅承运方；
- 喂养仅中/美方饲养员；兽医结论仅兽医；复核闭环仅指定兽医；
- 饲养员用药必须引用现行兽医结论；
- 跨境交接（`cross_border=True`）必须由中、美双方责任人共同确认。

## 7. 侧别可见性与时点回放

- 每条事件带 `visible_to`：`CN / US / BOTH`；
- `view_at(moment, side)` 以入链时间截断事件，再按侧别过滤，
  重放出现行照护计划版本、未恢复事件、最新体重、物资批次去向、交接记录、
  未决复核等；
- `dispute_export(moment)` 生成争议证据包：包含全部事件（含侧别标注与哈希）、
  链头哈希，以及 BOTH/CN/US 三份快照。中美双方日常看到的范围不同，
  但对同一时点拿到的是同一份可校验档案，可还原照护计划、物资去向与交接依据。

## 8. 模块划分

- `models.py`：侧别、角色、阶段、事件类型、范围、照护值对象、事件信封；
- `ledger.py`：只追加哈希链、校验、JSON 快照；
- `idempotency.py`：报告内容哈希幂等表与上传状态；
- `service.py`：权限、门禁、范围化影响、计划/喂养/用药/交接规则、
  矛盾复核、侧别视图、时点回放与争议导出。

事件信封结构见 `contracts/care-events.schema.json`。

# 领域边界

保存大熊猫跨境旅居的运输、检疫、照护记录与责任交接。

现有领域资料围绕以下边界组织：

- 动物身份与旅居协议
- 运输与检疫事件
- 照护计划与交接
- 物资与健康观察
- 争议时点回放

资料版本只能递增。参与方、事实和约束均不能为空，示例不得包含真实个人信息、账号或凭据。

# 照护档案规则（`src/transit_care.py`）

## 连续档案

照护旅程分为六个环节：出发前评估、装运封存、航程、入境检疫、入园适应、十年旅居。
每条记录都关联环节、动物（无动物归属的计划与批次除外）、发生时间、记录时间与责任人编号，
所有时间必须带时区，中美两地录入按同一绝对时刻排序。

记录按追加顺序形成哈希链：每条记录的哈希覆盖其全部内容与前驱哈希。
档案不提供修改与删除入口；`CareLedger.verify_chain()` 可发现任何外部篡改。
现场同步采集时记录时间默认等于发生时间；补录、迟报必须显式给出记录时间。

## 日常照护观察

喂养、用药、体重、行为异常均为普通照护观察，只能追加：

- 喂养须为正数量，引用饲料批次时校验品类一致与批次结余。
- 用药须含药品与剂量，只有饲养员和兽医可录入。
- 行为记录可关联多只动物并标注是否异常。

## 兽医结论锁定

兽医结论只能由兽医角色建立。结论确认后，饲养员与换班人员均无法改写；
兽医本人也只能以"兽医纠正"记录追加取代，纠正必须说明理由，原结论永久保留。
同一结论不能被二次纠正（须纠正最新的有效结论）。

## 偶发事件：作用域与恢复条件

检疫扣留、航线延误、饲料替代、单只隔离都是偶发事件，必须声明：

- 受影响环节（一个或多个），环节外一切照常；
- 原因与恢复条件；
- 单只隔离必须指明动物，其他动物不受影响；
- 饲料替代必须列出批准的替代饲料清单，且只在生效期间放宽计划约束，
  恢复后立即重新受原计划约束。

事件关闭同样是追加记录（记录恢复条件的落实情况），不回写原事件；
事件不能重复关闭。`contingency_active(kind, segment, animal, at)` 判定
某动物在某环节、某时点是否命中生效中的事件。

## 报告受理：幂等与矛盾复核

报告按内容哈希受理：

- 同一内容哈希重复提交，直接返回首次受理记录与最终状态，不产生新记录。
- 报告结论与该动物当前有效兽医结论矛盾时，不受理为既定事实，而是进入
  指定兽医（可按动物指定，另有默认兽医）的复核队列。
- 只有被指派的兽医可裁决，裁决必须写明依据：驳回则维持原结论；
  采纳则追加一条兽医纠正取代原结论。报告与裁决记录均保留。

## 饲料批次与交接

饲料按批次入库（批次号唯一、数量为正），喂养扣减批次结余，超量或品类不符被拒绝。
交接固定三方依据：指向当时有效的照护计划记录、移交的饲料批次清单，
以及交接所覆盖的记录序号区间，使事后能还原"当时交了什么、依据哪版计划"。

## 最小信息披露

记录可见范围分为：中美共享、仅中方、仅美方。双方视图只含共享记录与本方记录；
共同管理机构（JOINT）在争议调查时可见全部。兽医结论、偶发事件、报告与交接默认共享。

## 争议时点回放

`snapshot(as_of, viewer)` 按记录时间还原某一时点的状态：

- 各环节当时最新一版照护计划（旧版保留但不生效）；
- 生效中的偶发事件；
- 各饲料批次当时的结余（物资去向）；
- 每只动物当时有效的兽医结论；
- 尚未裁决的复核队列；
- 可见记录的哈希链校验结果。

视图与回放可以叠加：中方或美方只能在各自可见范围内还原时点状态。
